# MemoryPalace · 前端

React 前端，有两个模式：

- **演示模式（默认）**：不连后端，数据来自 `src/data.ts` 和 `src/chatData.ts`，用来确认设计。
- **真实模式**：连本地后端，总览和对话都走真实 API；当前是 **P1 可写 + 长期记忆**（写操作在聊天里确认）。

## 运行

```bash
cd demo
npm install
npm run dev
```

默认打开 `http://localhost:5173`，是演示模式。

### 连本地后端

先在 `server/` 启动后端（默认 `4310`，本机若被占用可用 `MP_PORT=4311`）：

```bash
cd ../server
MP_PROVIDER=mock MP_PORT=4311 npm start
```

再启动前端并打开真实模式：

```bash
VITE_MP_LIVE=1 MP_BACKEND_URL=http://127.0.0.1:4311 npm run dev -- --port 4173
```

`MP_BACKEND_URL` 只用于 Vite 的 `/api` 代理，不会写进浏览器代码。

生产构建：

```bash
npm run build
```

## 真实模式里能做什么

**总览**

- 工作区卡片显示真实路径、文件数、体积、主题数、最后索引时间和索引状态
- 「重建索引」调用 `POST /api/index/rebuild`，轮询 `GET /api/index/runs/:id`，完成后自动刷新
- 主题地图来自 `GET /api/overview`：主题、连线、文件构成都是索引算出来的
- 点主题后右栏从该主题对应的一级目录开始：先列子文件夹（带递归文件数），再列当前目录的直接文件；点文件夹逐层下钻，面包屑可回退，文件超过 50 个自动分页。数据来自 `GET /api/browse`
- 点文件调用 `POST /api/reveal`，在 Finder 里定位
- 索引活动、文件构成、最近提问同样来自真实数据
- 「健康与审计」读取 `GET /api/audit`，能看到真实的允许/拦截记录
- 「助手记忆」展开时读取 `GET /api/memories`，显示真实条数、类型、使用次数；可刷新，可逐条删除（`DELETE /api/memories/:id`）

**对话**

- 消息通过 `POST /api/chat` 的 SSE 流式返回
- 工具调用逐条出现：检索文件、搜正文、列目录、读元数据、读文本、Finder 定位
- 文件卡片来自工具返回的真实结果
- 正文命中有独立卡片：文件名、行号/页/段、片段、「打开所在文件夹」；语义参与时带「语义」「关键词+语义」小标记；文件里有可疑指令时会提示只当内容看
- 右侧显示正文命中、元数据命中、耗时和真实 token 用量
- 敏感文件会被后端拦截，界面只显示「敏感文件已拦截」，不会泄露路径或内容
- 写操作会在聊天里停下来：后端发 `confirm_required`，前端渲染确认卡，点「确认」后 `POST /api/confirm`
  - 新建 / 覆盖：卡片显示行级 diff（+ / −），点「确认写入」才落盘
  - 移动：显示源 → 目标，点「确认移动」才执行
  - 删除：先点「移入废纸篓」，再在警告下点「确认删除」；文件只进系统废纸篓
  - 点「取消」或 120 秒不操作，一律不执行；助手会如实说「没有改动」
- 说「记住：月报 = 季度经营分析报告」会在聊天里弹记忆确认卡，点「确认记住」才写入；写入后下一次会话自动带上

## 真实模式里还没有的

- **检索评估面板**：eval 目前是后端命令 `npm run eval:rag`，还没做成 Dashboard 实验区。
- **XLSX / PPTX / 图片正文**：正文索引覆盖文本、PDF（有文本层）和 DOCX；表格、演示、图片仍然只有元数据。
- **PDF/DOCX 全文阅读**：正文卡片只能引用检索片段（按页/段），`read_file` 仍只读文本文件。
- **rerank / query 改写**：阶段 2 已有本地向量 + 关键词混合检索，但排序仍然粗糙，语义命中需要人工核对片段。

## 哪些还是演示数据

只有 **演示模式（`VITE_MP_LIVE` 未设置）** 会用：

- `src/data.ts`：1,284 个文件、9 个主题、图表、记忆、审计、评估
- `src/chatData.ts`：对话剧本和工具调用

真实模式下，总览和对话的所有数字都来自后端索引与运行记录。

## 技术选择

- Vite 8 + React 19 + TypeScript，手写 CSS，没有 UI 框架和图表库
- 图标与图表都是内联 SVG
- 地图用单一蓝色顺序色阶 + 直接标签，没有用 8 种分类色
- 浅色和深色是两套独立取的色阶，不是简单反色
- 主题地图在窄屏会自动改成完整显示，避免两侧主题被裁掉
- Node 24 原生跑 TypeScript，前端没有额外构建层
